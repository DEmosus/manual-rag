# Manual RAG for IACS Rec. 47 - keyword vs embedding retrieval, a Laya decision gate, and an LLM wiki

A small, auditable question-answering tool over **PDF pages 4-8 of IACS Recommendation 47** ("Shipbuilding and Repair Quality
Standard"). It finds the relevant manual text first, answers by **copying a sentence from it with PDF-page citations**, and returns
**"The supplied pages do not specify an answer."** when the manual does not contain the fact. Every reported number is produced by
code from the saved per-question outputs; nothing is typed in by hand.

| Part            | What it does                                                                                                                           |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **Task 1**      | Compares two retrievers over identical chunks: a _keyword baseline_ and _embedding search_ (`sentence-transformers/all-MiniLM-L6-v2`). |
| **Extension 1** | **Laya** reads the question and the three retrieved chunks and chooses `answer` or `abstain`.                                          |
| **Extension 2** | Rebuilds the same pages as a cited **wiki** (index + 3 linked topic pages) and runs the same search and answer code on it.             |

> New here? Read **[EXPLAINER.md](EXPLAINER.md)** - it explains every file, how they connect, and walks single questions through the code.
> The short submission report is **[REPORT.md](REPORT.md)**.

## 2. Quick start

Requires Python 3.10+ (Laya needs 3.10+). Tested on Windows with Git Bash; nothing is platform specific.

```bash
python -m venv .venv
source .venv/bin/activate                  # Windows Git Bash: source .venv/Scripts/activate
pip install -r requirements.txt            # core: pymupdf, numpy, pytest (versions pinned)
pip install -r requirements-extras.txt     # embeddings + Laya (torch etc.; large)
# place the supplied PDF at materials/IACS_47_Steel_Shipbuilding_Quality_2025.pdf  (not committed; see .gitignore)
python run_all.py                          # runs the whole protocol in the right order, then fills in the results above
```

`python run_all.py` needs no credentials. The first run downloads the embedding model (~90 MB) and the Laya checkpoint (~847 MB). Both are cached by Hugging Face afterwards. Setting `HF_TOKEN` is optional and only removes
the "unauthenticated requests" warning. Only the keyword baseline and the wiki need nothing beyond `requirements.txt`.

## 5. How an answer is produced

1. **Chunks.** Pages 4-8 are cut into 22 clause-level chunks. Each knows its original 1-based PDF page; the gas-cutting tables keep their
   `Standard Limit` header with their values.
2. **Retrieve.** Keyword (distinct shared words, ties by document order) or embedding (cosine similarity of `all-MiniLM-L6-v2` vectors,
   kept in memory) returns the top 3 chunks.
3. **Decide.** Each content word of the question is weighted by rarity in the manual (a word found nowhere weighs the most). _Coverage_ is
   the share of that weight present in a chunk. If the best of the three chunks covers **less than 50 %**, the answer is the fixed refusal
   sentence with no pages. A high rank alone is never treated as evidence.
4. **Copy.** Otherwise the best-matching sentence(s) of the best chunk (or, for a table, the header plus the matching row) are copied and cited.

The decision and copy steps are identical for both retrievers and for the wiki, so differences in results come from what changed.

## 6. Choosing the retrieval method

The extensions use one retriever, selected from **dev results only** (`SELECTED_METHOD` in `config.py`).

**Rule:** highest dev retrieval hits; if tied, higher dev correct supported answers; if still tied, **keyword** (simplest, deterministic,
needs no model download).

**Dev outcome:** keyword 5/5 hits and 5/5 answers; embedding 5/5 hits and 5/5 answers -> a tie on every required metric -> **keyword**.

Transparency notes:

- An extra, non-required statistic favours embedding: it placed 11 of 15 top-3 chunks on an expected page against 9 of 15 for keyword
  (`Dev top-3 chunks on an expected page` in the table). It was _not_ used to decide, because the rule above was fixed first on the
  required metrics.
- The tie-break rule was written after the tie was observed. Keyword was already the working default, and keyword's test numbers had been
  seen in earlier iterations of this project, so switching now would mean choosing with that knowledge.
- To use embedding instead: set `SELECTED_METHOD = "embedding"` in `config.py`, then run `python run_all.py --force`. The freeze guard
  forces fresh dev runs first.

## 7. Evaluation protocol

- **Questions:** `data/questions.json`, exactly as supplied: dev q1-q5, test q6-q10; q9 and q10 are unanswerable (empty page list).
- **Retrieval hit** (answerable only): some top-3 chunk is on an expected page **and** contains the key evidence text from
  `data/answer_keys.json`. A page match alone is not a hit.
- **Correct supported answer:** the system answered, the answer contains every key string, and a cited page is expected. Answers are
  copied from retrieved text, so they are supported by it by construction.
- **Correct missing-evidence response:** unanswerable question, answer is the fixed sentence, no supporting pages. An abstention caused by
  a Laya error does **not** count; it is reported as a Laya runtime error.
- **Dev vs test:** settings were tuned on dev only. `run_eval.py test` runs only if a dev result exists whose **fingerprint** equals the
  current one (sha256 of `config.py`, `retrieve.py`, `answer.py`, `pdf_to_chunks.py`, the questions and keys, plus the wiki files and wiki
  prompt for the wiki system, or `laya_gate.py` and `prompts/laya_question.json` for Laya). If anything changed, re-run dev, then test.
  It also refuses to overwrite a finished test result without `--force`.
- **Output contract:** every record has `question_id`, `retrieved_chunks` (`chunk_id`, `pdf_page`, `text`, + score/rank/wiki file),
  `decision`, `answer`, `supporting_pdf_pages`; an answer must have pages, an abstention must be the fixed sentence with no pages
  (checked in code on every record).

Changes made during dev (all motivated by dev questions): the stop-words `difference`/`between` (dev q2 abstained), `MAX_SENTENCES` 3 -> 5
(dev q2 lost a sentence), and a stemmer rule so `qualification` ~ `qualified` (found while testing dev q3).

## 8. Extension 1: Laya

[Laya](https://huggingface.co/convaiinnovations/laya) (PyPI package `laya`, author Convai Innovations) reads a text and answers typed
questions in one pass. Here it gets **one `choice` question with two labels, `answer` / `abstain`**, and a text made of the question plus the
three retrieved chunks (with their PDF pages).

- Retrieval is the selected Task 1 method, unchanged; its outputs are saved first as the baseline (`outputs/*_pdf_*.json`).
- `answer` -> the existing answer code copies the sentence (`use_threshold=False`: Laya replaces the built-in 50 % coverage check as the
  sufficiency judge; sentence picking is unchanged). `abstain` -> the fixed sentence, no pages.
- Any failure (crash, invalid or unexpected label) -> abstain, the error is recorded, and it is counted separately as a **Laya runtime error**.
- The question text is frozen in `prompts/laya_question.json` (hashed by the freeze guard). Every question's **actual Laya input, raw
  output, label and error** are saved separately in `outputs/<split>_laya_<method>_laya_log.json` with the Laya package version, the
  checkpoint (`convaiinnovations/laya`, subfolder `typed-decisions`), its Hugging Face revision and the prompt hash.
- Download/memory: checkpoint 847 MB; also needs `torch`. On load, Laya prints a warning that this checkpoint ships invalid temperatures for
  some heads (`choice:11+` -> 0.5) and that **confidence values are uncalibrated**. This project uses only the chosen _label_, never the
  confidence, so the warning does not affect the decision.
- Laya can only change answer-vs-abstain. It cannot repair a case where the right chunk was found but the wrong sentence was copied.

## 9. Extension 2: wiki

`wiki/` holds `index.md` and three linked topic pages (44 cited claims). Every fact is one bullet ending
`(Source: IACS Rec. 47 Part A, Sec. X, PDF page N.)`; tables are markdown tables under a cited line. `wiki_tools.load_wiki_chunks` turns
each bullet and table into a chunk with the same fields as a PDF chunk (plus the wiki file), then `run_eval.py --system wiki` uses the **same
retriever and answer code**. Each wiki answer cites the **wiki file and the original PDF page**; the retrieved wiki text is saved with every
answer so a reviewer can trace it back to the PDF. `python wiki_tools.py` validates the wiki.

Provenance (full text in `prompts/wiki_provenance.md`) no API call, so there is no model snapshot id. The author had seen the evaluation questions beforehand, so the
wiki-vs-PDF comparison is **not blind**. The wiki also stays close to the manual's wording, so its main effect is changing the chunk size
(one claim vs one clause), not adding knowledge. Five pages say nothing about larger collections.

## 11. Mistakes and limitations

1. **Test q6 (PDF and wiki, keyword): right chunk, wrong sentence.** Retrieval hit clause 3.1.2 (`p5-3.1.2-01`, coverage 0.89) but the copied
   sentence was the first one ("...fully mechanized or fully automatic processes need generally not pass approval testing...") because the
   question repeats those words; the sentence that answers ("Records of training and operation experience shall be maintained...") shares
   only "records" and "training". Word overlap cannot tell what is being asked.
2. **Wiki test q8: the table chunk lost its context.** The wiki table chunk holds only the label, header and rows, so the cited intro bullet
   ("The roughness of the cut edges is to meet the following requirements...") had higher coverage (0.80) and was copied instead of the
   values. In the PDF the table chunk carries the clause heading and intro, and the answer was correct. Wiki dev q2 also lost a three-way
   keyword tie, because the wiki splits text into many small bullets.
3. **The abstention rule is lightly validated.** Test q7 passed at coverage 0.515 against a 0.5 threshold; the unanswerable questions scored
   0.15 (q9) and 0.22 (q10) for the PDF. Only two unanswerable examples exist and neither is topically close to the manual.
4. **Answers can carry neighbouring text** when no sentence punctuation separates rows (dev q5 returns the whole definitions block).
5. **Laya:** its confidence output is uncalibrated for this checkpoint (unused here), and it cannot fix wrong-sentence cases like q6.
6. Ten questions over five pages cannot establish that one method is better than another.

## 12. Reproducibility

- Python version, package versions, git commit, settings, fingerprint and model revisions are stored inside every `outputs/*.json`;
  `requirements-lock.txt` is the full `pip freeze` of a finished run.
- Pinned core versions (`requirements.txt`): `pymupdf==2.0`, `numpy==2.4.4`, `pytest==9.1.1`. Extras (`requirements-extras.txt`):
  `sentence-transformers>=3.0`, `laya==0.4.15`.
- **Models:** embedding `sentence-transformers/all-MiniLM-L6-v2`; Laya `convaiinnovations/laya`, subfolder `typed-decisions`;
  wiki author Claude Sonnet 5.5 (chat).
- **Environment variables: none are required.** `HF_TOKEN` is optional (Hugging Face rate limits).
- Keyword results are deterministic. The only manual text correction is the font glyph U+F0A3 -> "≤" in Table 1 (page 6).

## 14. Troubleshooting

| Message                                                               | Meaning / fix                                                                                             |
| --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `... already exists (final result). Use --force`                      | A finished test result is protected. Re-run with `--force` only if you intend to redo it (deterministic). |
| `code/settings/wiki/prompt changed since the last dev run`            | You edited something the freeze covers. Re-run the dev split, then test.                                  |
| `run the dev split first`                                             | A test run needs a matching dev run.                                                                      |
| `NOT RUN: sentence-transformers is not installed` / Laya import error | `pip install -r requirements-extras.txt`.                                                                 |
| `PDF not found`                                                       | Put the supplied PDF at `materials/IACS_47_Steel_Shipbuilding_Quality_2025.pdf`.                          |
| `unauthenticated requests to the HF Hub`                              | Harmless; set `HF_TOKEN` to silence it.                                                                   |
| Laya `RuntimeWarning` about temperatures                              | Known for this checkpoint; confidence is not used (section 8).                                            |
